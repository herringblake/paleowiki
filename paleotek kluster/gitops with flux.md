# GitOps with Flux

Flux runs in the cluster, pulls the `learn_kubernetes` repository from GitHub (read-only deploy key), and keeps the cluster equal to the `flux/` folder. **Deploying something means committing it.** A change made by hand with `kubectl` or `helm` is reverted at the next reconcile (every 10 minutes, or sooner after a push).

Work happens on feature branches merged by pull request. CI runs on every pull request and on pushes to `main` (see [[Repository and conventions|paleotek kluster/repository and conventions]]). Merging to `main` deploys, and Flux holds cluster-admin, so whoever can push to `main` can change the cluster.

## Layout

- `flux/clusters/main/` is the entry point: Flux's own components (`flux-system/`, generated by `02`, never edited by hand) and `apps.yaml`, a Flux Kustomization that applies `flux/apps/`.
- `flux/infrastructure/` (cert-manager, issuers, Gateways), `flux/apps/` (Headlamp, Otterwiki, the nginx sites), `flux/monitoring/`, `flux/metrics-server/` and `flux/notifications/`. Each app is a folder of plain manifests, or a `HelmRepository` and a `HelmRelease`.
- The Kustomizations form a dependency chain (`dependsOn`): if one fails, everything downstream freezes. For example, a missing intranet CA Secret holds up `infrastructure-configs` and so every app.

## What stays as scripts

The host and the day-0 bootstrap: node prep, containerd, kubeadm, kubelet CSRs, Cilium's first install, the StorageClasses, the backup timer, the CA root, DNS and the router. Flux manages what runs *in* the cluster, and takes apps over one at a time.

## Settings and the repository URL

Manifests contain **no personal values**. Settings are written as `${NAME}`, and Flux fills them from the ConfigMap `flux-system/cluster-vars`, which `scripts/flux/01-cluster-vars.sh` builds from `env.sh`. Re-run `01` after changing `env.sh` or after adding a `${NAME}` to a manifest.

- The repository URL is also kept out of git: `03-install-flux.sh` creates the connection from `FLUX_GIT_URL` in `env.sh`.
- In YAML flow style (`[...]`, `{...}`) **quote** a `${NAME}`, or the braces break parsing.
- Substitution is **strict**: kustomize-controller runs with the `StrictPostBuildSubstitutions` gate (patched in `flux/clusters/main/kustomization.yaml`), so a variable missing from `cluster-vars` fails the Kustomization and applies nothing, instead of becoming an empty string. `01` also fails on any name `env.sh` lacks.
- Flux skips substitution entirely when `cluster-vars` has no variables, so `01` always adds the sentinel `CLUSTER_VARS_LOADED`.
- A feature-gate name that Flux does not know crashes the controller, and Flux applies its own changes. Check a new gate against a throwaway pod of the same image before committing it (see the comment in that file).

## One-time setup

1. Install the Flux CLI (pinned in `02-generate-flux-system.sh`): download `flux_<version>_linux_amd64.tar.gz` and `flux_<version>_checksums.txt` from the fluxcd/flux2 GitHub release, check the SHA-256, put `flux` in `~/.local/bin`.
2. `scripts/flux/02-generate-flux-system.sh`, then commit and **push** `flux/` (the cluster reads the remote, not your disk).
3. `scripts/flux/01-cluster-vars.sh`, then `04-sops-key.sh` (the decryption key; see [[Secrets in git|paleotek kluster/secrets in git]]), then `03-install-flux.sh`. If GitHub does not accept the deploy key yet, `03` prints the public key and the settings page; add it as a **read-only** deploy key and re-run. It then waits for Flux, the apps and the Headlamp release to be healthy.

## Day to day

- Edit under `flux/`, run `scripts/flux/test-flux.sh` (offline: builds everything and checks that every variable resolves), commit on a branch, open a pull request.
- Watch with `flux get all -A`. Preview against the live cluster with `flux diff kustomization apps --path flux/apps`.
- **Never `kubectl apply` an object Flux owns.** The old imperative scripts for migrated apps were removed for that reason.
- **Every PersistentVolumeClaim under `flux/apps` must carry `kustomize.toolkit.fluxcd.io/prune: disabled`** (`test-flux.sh` enforces it). A volume holds data that git does not, and Flux would delete it if its manifest were ever removed.
- **Moving an app from scripts to Flux:** copy its manifests under `flux/apps/<app>/` with the same names and namespaces, and check that `kubectl diff` shows no difference. For a Helm release, give the `HelmRelease` the same name and namespace as the existing release, with the same chart version and values, so Flux upgrades it instead of installing a second copy. **Never rename a release:** Flux would uninstall the old one.
- cert-manager's own auto-created Certificate for the public Gateway carries Flux's label (inherited from the Gateway) but is not in Flux's inventory, so Flux never prunes it.

## When it goes wrong

`kubectl -n flux-system describe kustomization <name>` names the problem. Failures also reach you by two routes: a Prometheus alert and Flux's own notifications ([[Flux alerts|paleotek kluster/flux alerts]]).
